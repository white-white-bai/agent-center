# 真实模型业务问题端到端抽样报告

> 日期：2026-10-29
> 模型：`deepseek/deepseek-v4.1-flash`（备用 `deepseek/deepseek-v4-flash`）
> 环境：Docker 本地栈（app + MySQL + Redis + 内嵌 Milvus Lite）
> 抽样脚本：`scripts/e2e_sample.py`，每次使用独立租户，不污染既有数据

## 一、抽样设置

- 知识库：区级业务 5 篇 + 公共资源交易 3 篇，覆盖营业执照、社保卡、公积金、居住证、新生儿落户、投标保证金、招投标异议、CA 证书
- Agent：区级政务咨询、公共资源交易咨询、事项办理助手（含必填槽位）
- 问题集：19 组，覆盖政策问答、跨域路由、缺信息澄清、多轮槽位、无知识兜底

## 二、结果汇总

| 指标 | 结果 |
| --- | --- |
| 请求数 | 19（另含 1 组两轮对话） |
| 硬错误 | 0 |
| 路由准确率 | 100%（19/19） |
| 引用命中率 | 100%（9/9 有引用的完成回答均返回 citation） |
| 关键词命中率 | 100%（9/9 有预期关键词的问题均命中） |
| 完成/等待澄清 | 18/19（1 题路由不确定，返回澄清引导） |
| 多轮槽位 | 2/2 槽位正确落库（matter_type、application_number） |
| 延迟 P50 | 8.4s |
| 延迟 P95 | 34.6s（单题长回答，最长 34.6s） |

典型结果：
- “营业执照办理需要哪些材料” → 命中知识库，回答身份证/申请书/场所证明，返回 5 条引用
- “投标保证金怎么退” → 路由到公共资源交易 Agent，引用《投标保证金退还指南》，答出材料与 5 个工作日
- “我要办理营业执照” → 追问申请编号；补充“A2026001”后完成回答，两个槽位均持久化
- “跨省通办有哪些事项” → 路由置信度不足，返回澄清引导而非报错

## 三、本轮发现并修复的问题

1. **知识检索不匹配标题**：原先只检索切片正文，标题中的关键词（如“新生儿落户”“投标保证金”）搜不到，引用率为 77.8%。修复为标题 + 小节 + 正文联合匹配后，引用率达到 100%。
2. **路由不确定返回 409**：Supervisor 低置信度时直接抛冲突，用户看到错误页。改为 SSE 澄清响应（`message.delta` + `message.end`，`finishReason=waiting_user`）。
3. **槽位指令不够强**：模型倾向直接追问而不记录槽位。提示词增加“用户提供必填槽位值时先输出 slots”，两轮槽位均成功落库。
4. **备用模型配置错误**：`deepseek/deepseek-v4.1` 不在模型目录，返回 400；已改为 `deepseek/deepseek-v4-flash` 并验证可用。

## 四、仍未达标项

| 项目 | 现状 | 建议 |

| 端到端延迟 | P50 8.4s、P95 34.6s，超过概要设计 P95 ≤ 8s | 使用 `deepseek-v4.1-flash-fast` 变体、限制回答长度、按需流式输出，并以首 token 延迟和完整回答延迟分开统计 |
| 抽样集代表性 | 当前为贴近业务的人工构造问题集 | 用现有 chatflow 的真实问题与标准答案替换，重新跑同一脚本 |
| 工具执行 | 本次未覆盖真实业务工具（无可用测试接口） | 提供业务测试环境后，增加“进度查询/材料提交”场景 |
| 引用准确率 | 本次只统计“是否返回引用”，未逐条核验引用是否支持结论 | 结合评测集做引用准确率人工/模型抽检 |

## 五、复现方式

```bash
docker cp scripts/e2e_sample.py agent-center-app:/tmp/e2e_sample.py
docker compose exec -T app python /tmp/e2e_sample.py
```

脚本会自动创建独立租户、知识库与 Agent，输出逐题明细与汇总 JSON。
